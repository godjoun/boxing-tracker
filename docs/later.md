**지금은 기능을 더하지 않는다.**  
기존 화면의 사용성·정보 구조를 출시 품질로 완성한다. 불필요한 것은 지운다.

### 출시 품질 판단 (항상 우선)

1. 사용자가 생각하지 않고 사용할 수 있는가?
2. 정보가 한눈에 들어오는가?
3. 한 화면에서 해야 할 행동이 하나로 명확한가?
4. 불필요한 기능이나 정보는 없는가?

### 화면 완성 순서 (갱신 · 2026-08-04)

**지금 우선:** 커뮤니티 IA/UI (`docs/community-ia.md` · `docs/community-ui.md`)  
→ 구현 승인 후 커뮤니티 UI  
→ 이어서 홈·훈련·기록·전체·프로필·성장 출시 품질

Vision Loop (고정):  
`훈련 → 기록 → 교류 → 프로필에 흔적 → 신뢰 → 새로운 교류 → 다시 훈련`

- 관↔관 본구현은 출시 후 + 실사용 피드백 (`docs/gym-exchange.md`)
- 홈 구조 패스는 일부 반영됨 · 커뮤니티 잠금 후 이어서 다듬음

### 라이벌·스파링 파트너 (출시 숨김 · 심화는 Level 3)

> 참고 화면의 카드 모양을 복제하지 않는다. 공개 프로필을 빠르게 찾고, 상대가
> 동의한 뒤에만 대화하는 흐름만 참고한다.

**상태:** 안전·차단·신고·동의 운영 전까지 **출시 화면에서 숨김**.
코드·SQL 자산은 유지하고 `RELEASE_SCOPE.rivals`로 다시 켤 수 있다.
채팅·차단·신고·권한 모델 심화는 별도 Level 3 승인 후 진행한다.

**Level 3인 이유:** 공개 프로필, 개인정보 공개 범위, 위치 정보, 요청 기반 채팅,
차단·신고와 운영자 조치가 하나의 데이터·권한 모델로 연결된다. 착수 시 Product → UX
→ Backend → Security → Data → 구현 → 리뷰 → QA → 출시 승인을 모두 거친다.

#### 기능 범위 후보

1. 공개 라이벌 프로필 목록
2. 프로필 상세 보기
3. 지역·체급·경력·소속 체육관 정보
4. `스파링 파트너` 또는 `훈련 파트너` 목적 표시
5. 대화 요청 후 상대가 수락한 경우에만 채팅 가능
6. 프로필 공개/비공개 설정
7. 사용자 차단·신고와 운영자 처리 상태
8. 정확한 위치·현재 위치·이동 기록은 공개하지 않고 대략적인 활동 지역만 표시

#### 제품·안전 경계

- 연락처, 정확한 주소, 실시간 GPS는 공개 프로필과 채팅 진입 전에 노출하지 않는다.
- 공개 전 명시적 동의, 비공개 전환, 차단 즉시 노출·요청·채팅 차단을 함께 설계한다.
- 대화는 일방 요청만으로 열리지 않는다. 상대의 명시적 수락이 필요하다.
- 체급·경력·소속 체육관은 사용자가 입력한 정보임을 표시하고 검증 정보처럼 단정하지 않는다.
- 신고는 단순 버튼으로 끝내지 않고 사유, 증거 보존 기간, 운영자 처리, 이의 제기와
  재가입 방지 범위를 결정한 뒤 구현한다.

#### 착수 조건

- 기록·훈련·짐 핵심 화면의 모바일 흐름과 공개 베타 회귀 검증이 끝났다.
- 최소 한 지역에서 실제 스파링·훈련 파트너 수요와 공개 의사를 확인했다.
- Supabase RLS, 요청/수락 상태 전이, 차단 관계, 신고 운영 정책과 보존 기간을 설계했다.
- 프로필 공개 범위와 위치 비식별 기준에 대한 CEO의 명시적 승인을 받았다.

#### 이번 후보에서 제외

- 정확한 거리 순 정렬, 실시간 위치, 이동 경로
- 연락처 공개, 요청 즉시 채팅
- 공개 랭킹·외모 평가·후기 점수
- 자동 매칭, AI 추천, 푸시 알림

| 칩 | 지도에 올리는 것 | 비고 |
|----|------------------|------|
| 체육관 | 입점·OSM 핀 | 이미 됨 |
| 대여 | 같은 입점 핀 → 문의 kind=`rental` | 별도 핀 아님 |
| 모임 | 일정 주소 핀 | 올리기 때 위치 찍기 선행 권장 |
| 라이벌 | 지역 원/클러스터 + 카드 | 정확한 주소 핀은 약함 |

**지금 하지 않음.** 특히 라이벌 칩·핀은 위 Level 3 승인 전 출시 범위에 넣지 않는다.

**착수 타이밍 (아래를 만족하면 그때 하자):**

1. **출시·소프트 론칭 안정** — 모임 올리기·참가·문의 채팅·지도 찾기가 실사용으로 돌아가고
2. **군산·근처 입점 좌표**가 몇 곳이라도 지도에 실제로 찍히고
3. **모임 일정에 위도·경도**를 저장할 준비가 됐을 때

그 전에 치면: 탭·채팅·입점 운영이 흐트러짐.  
**신호:** 「군산 입점 3곳+ 지도에 보인다」또는 「모임에 위치 찍기가 붙었다」→ 그때 지도형 도장 개편 착수.

### 지금 해도 되는 것 (출시 전 · 한 화면씩)

0. **짐 지도 허브** ← **완료** — 체육관 지도 기본 진입 · 라이벌 찾기 · 찜
1. **입장 흰 화면 배너** — MANTLE + 슬로건 + 철학 한 줄 ← **완료** (`EntryBanner`)
2. **모임 UX 알기 쉽게** — 올리기·참가·대화 한 줄 안내 ← **완료**
3. **문의 채팅 쓰기 쉽게** — 폴링·카피·관장 받은 문의 경로 안내
4. **링 타이머 정리** — 한 화면에 보기·입력 쉽게 · 군더더기 제거
5. **명패 공유를 이미지로** — 지금 공유가 시트만이면 카드 이미지로 (html-to-image 이미 의존성 있음)
6. **군산·근처 입점 발품** — 제품 코드보다 운영 · 라이벌 카드는 Level 3 착수 전까지 모집하지 않는다

### 나중 (메모의 큰 덩어리)

- **관↔관 교류 (Level 3)** — 설계 잠금 `docs/gym-exchange.md`. 출시 직전 구현 금지. 제안·일정·완료 기록·프로필 흔적만 1단계. 피드·배지·랭킹 제외
- **출시 칩 정리** — `체육관 · 라이벌 · 모임` (찜 칩 삭제→필터). 코드 미반영이면 Level 1–2로 가능
- **메시지 알림** — 전역 안 읽음 뱃지 · 알림 센터 · 웹 푸시/기기 푸시를 함께 설계
- 관장/회원 시작 분리 또는 앱 분리
- 로그인 + “제3자 제공 안 함” 안심 화면
- 지역 광고 배너 (`is_featured`)
- 관 상세 커뮤니티·만족도·댓글
- 입문자 장비 가이드(스토어 카탈로그형 · 가챠 아님)
- 알림음에 사용자 노래 추가 (가능하면)
- Apple Watch / 영상 필터 다운로드
- 생체 대회·실시간 대진·사진 이벤트
- 광고·커리큘럼·용품 판매 파이프 (배민·아정당형 · `monetization.md`와 동일)

### 모임에 비어 있던 칸 (채워 둠)

- **올리기:** 커뮤니티 → 모임 → 일정 올리기 → 관·주소·날짜·시간·인원·참가비
- **참가:** 카드 → 참가 신청 → (서버) 대화하기 / 신청 취소
- **이유:** 주말에도 운동하고 싶다 · 문을 연 관을 알리고 싶다 · 여러 사람과 스파링하고 싶다
- **대여와 구분:** 주말 관 대여는 **체육관 문의** 종류(대여)
- **교류와 구분:** 관↔관은 `docs/gym-exchange.md` (별도 · 출시 후)
