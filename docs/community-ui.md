# 커뮤니티 UI 설계 — 승인용

> **상태:** 미래 확장 참고 설계. 현재 출시 UI 구현 범위가 아니다.
> 현재 Core Loop와 우선순위는 `docs/product-philosophy.md`를 따른다.
> **전제:** IA 잠금 `docs/community-ia.md` · Vision Loop · Community Principle 고정.  
> **상태:** 커뮤니티 첫 화면 = **피드**. 상단 `피드 | 교류 | 체육관 | 모임` (스파링·라이벌 출시 숨김). 교류 안 `제안 | 일정 | 뱃지 | 랭킹`. 상세=카드 진입. 좋아요 없음.  
> 출시 색: 기본 화이트 · 다크 버건디 `#8A2E2E` (전면 화이트 테마는 다음 작업).

## 설계 원칙

1. 한 화면 한 행동  
2. 허브 = 다음 교류 / 프로필 = 지난 증명  
3. 메인 CTA 화면당 버건디 하나  
4. 기존 기능 유지 · 정보 구조·계층·여백·CTA만 재배치  
5. Vision Loop에 역할 없는 UI 블록 추가 금지  
6. **Community Principle:** 새 교류를 만들거나 프로필 신뢰를 높이는가?  
   좋아요·조회수·배지 경쟁보다 실제 복싱 활동 우선 (`docs/community-ia.md`)

## 화면 지도

```text
커뮤니티
├─ C0 게이트 — 지역 (체육관 탭)
├─ C1 게이트 — 내 체육관 (선택·건너뛰기 가능)
├─ C2 피드 ← 기본 랜딩 (카드 · FAB)
├─ C2b 교류 도구 (제안 · 일정 · 뱃지틀 · 랭킹틀)
├─ C3 체육관 목록/지도
├─ C4 체육관 상세
├─ C5 스파링/라이벌 목록
├─ C6 라이벌 카드/상세
├─ C7 모임 목록
├─ C8 모임 상세 · 신청
├─ C9 나 (개인 활동)
├─ C10 대화 (문의/모임/라이벌 — 기존 모달 재사용)
└─ (프로필 P1) 교류의 흔적 — 커뮤니티 결과 면
```

관↔관 전용 화면은 **출시 UI에 넣지 않음**. 교류에 「이후」자리만.

## C1 · 내 체육관 게이트

| 항목 | 내용 |
|------|------|
| 주인공 | 다닐 관 고르기 |
| 한 행동 | 내 관 등록 **또는** 나중에 |

## C2 · 피드 — 커뮤니티 첫 화면

상단 칩: `피드 | 교류 | 체육관 | 모임` (스파링·라이벌은 출시 숨김)

| 항목 | 내용 |
|------|------|
| 주인공 | 다음에 고를 만남 카드 |
| 카드 | 아바타 · 관명 · 지역 · 시간 · 상태 · 본문 · 사진자리 |
| 한 행동 | 카드 → 상세 |
| 주 CTA | FAB `+` → 모임 올리기 |
| 없음 | 좋아요 · 댓글 · 공유 카운트 |

## C2b · 교류 — 도구 카테고리

```text
제안 | 일정 | 뱃지 | 랭킹
```

카테고리를 고르면 **그 기능에 맞는 틀**로 바뀐다.  
상세는 카테고리가 아니라 **피드 카드**에서 들어간다.

| 카테고리 | 틀 | 주 CTA | MVP |
|----------|-----|--------|-----|
| 제안 | 제안서 골격 → **제안서 작성** | 제안 보내기 | ✅ |
| 일정 | 예정/진행/완료 + D-day | + 일정 만들기 | ✅ |
| 뱃지 | 프로필 흔적 안내 | 내 흔적 보기 | 틀만 |
| 랭킹 | MVP 제외 안내 | 일정으로 돌아가기 | 틀만 |

### C2-Detail 교류 상세 (카드에서 진입)

| 블록 | 내용 |
|------|------|
| VS | 주최 ↔ 신청/모집 |
| 요약 | 상태 · 제목 · 일시 |
| 정보 | 일시 · 장소 · 인원 · 참가비 |
| 사진 | 플레이스홀더 (실시 후 기록) |
| 안내 | 한줄 노트 |
| CTA | 참가 신청 / 대화 |

### 공통

| 규칙 | 내용 |
|------|------|
| 상단 | 카테고리 + 현재 화면 제목 |
| CTA | 화면당 버건디 **하나** |
| 카드 | 의미 하나 |
| 금지 | 좋아요·댓글·배지 경쟁·공개 랭킹 본기능 |

### C2-A 교류 피드

| 항목 | 내용 |
|------|------|
| 목적 | 다음에 고를 만남 목록 |
| 주인공 | 교류 카드 |
| 주 CTA | + 모임 올리기 |
| 다음 | 카드 → 교류 상세 |

### C2-B 교류 제안

**구현 (2026-08-05):**

- **본거지** = 입점 체육관 상세의 작은 `교류 제안` 버튼.
- **보조** = 허브 제안 → `체육관 찾기` → 상세.
- **전송** = 기존 예약 문의 형식 + 제안 표식. 보낸 뒤 관장과 기존 메시지로 조율.
- **미입점·OSM** = 받을 관장이 없으므로 제안 없음. 전화·홈페이지(데이터가 있을 때)·길찾기만.
- 관↔관 수락·상태·완료 기록 스키마는 출시 후 (`docs/gym-exchange.md`).

### C2-C 교류 일정

예정·진행·완료 + D-day. CTA: + 일정 만들기.

### C2-D 교류 상세

카드에서 진입. 신청 / 대화.

### C2-E 뱃지 · 랭킹

카테고리 자리만. 배지→프로필 흔적. 랭킹→넣지 않음.

## P1 · 프로필 「교류의 흔적」

커뮤니티 탭 밖이지만 **Loop의 정점**이라 UI에 포함.

```text
교류의 흔적
  교류 N · 스파링 N · 관 N     ← 요약(뼈대, 조용히)
  ─ 최근 ─
  [유형] 제목 · 장소 · 날짜     ← 주인공 = 이력 카드
  [유형] …
  전체 이력 →
```

| 항목 | 내용 |
|------|------|
| 주인공 | 최근 이력 카드 |
| 한 행동 | 이력 읽기 (상세는 이후) |
| 금지 | 랭킹, 배지 그리드, 좋아요 |
| Loop | 신뢰 → 허브로 「새로운 교류」유도 링크 가능 |

완료 직후(모임·스파링 기록 저장 시) 짧은 확인:  
「프로필에 오늘이 남았습니다」→ 프로필 / 닫기.

[브랜드/타이틀]                    [나]

- 허브가 기본 · 다른 칩은 깊은 파기

## 구현 단계 제안 (승인 후)

1. **IA 반영 UI** — 칩 `교류·체육관·라이벌·모임` · 허브 골격 · 찜 필터 · 「나」진입  
2. **프로필 교류의 흔적** 블록(자리 + 기존 데이터로 채울 수 있는 것)  
3. 허브←→기존 체육관·라이벌·모임 연결  
4. 관↔관 · 고도 출석 = 이후 (`gym-exchange.md`)
