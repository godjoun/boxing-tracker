# Evidence Rule

## 문서 정보

- 소유: SDS
- 독자: CEO, AI 팀, 개발자
- 읽는 시점: Pattern·Lesson·Anti Pattern을 기록하거나 근거로 제안할 때

## 원칙

증거 없는 주장을 사실처럼 말하지 않는다. 증거가 부족하면 “가설”, “관찰”, “확인 필요”로 표시한다.

## 인정하는 증거

- 사용자 인터뷰, 설문, 사용성 테스트
- 제품 분석·오류·성능 데이터
- 재현 가능한 실험과 검증 결과
- 명시된 출처가 있는 외부 연구

## 기록 형식

원본 증거는 프로젝트 `docs/`에 아래 정보를 포함해 남긴다.

```text
날짜:
출처:
대상 또는 표본:
관찰 사실:
한계:
원본 위치:
```

SDS Memory에 항목을 올릴 때는 원본 위치, 관찰한 사실, 적용 범위, 신뢰 한계를 함께 적는다.

## 금지

- 개인의 추측을 사용자 전체의 의견으로 일반화하지 않는다.
- 표본·출처·날짜 없이 수치나 반응을 인용하지 않는다.
- 하나의 프로젝트 증거를 모든 제품에 그대로 적용하지 않는다.
