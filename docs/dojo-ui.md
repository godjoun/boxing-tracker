# 짐 화면 구조

> UI 복제 금지. **흐름·자리만** 빌린다.  
> 제품: `docs/dojo.md` · 수익: `docs/monetization.md`

## 최상위 구조 (현재)

첫 화면은 **지역 선택 → 목록**이다. 지도는 보조 무대다.

### 첫 사용 (지역 없음)

지역/위치가 없으면 **한 행동만** 보여 준다.

| 자리 | 내용 |
|------|------|
| 상단 | 커뮤니티 타이틀 · 카테고리 `체육관 · 라이벌 · 모임` · 지역 선택 필 |
| 하단 시트 | **지역 선택**(주 CTA) · 내 주변으로 찾기 · 추천 지역 칩 |
| 보조 | 문의·더보기는 지역 확보 후 |

지역이 잡히면 아래 목록에 체육관이 나열되고, 지도는 뒷배경·미리보기용이다.

## 최상위 구조 (지역 확보 후)

| 자리 | 내용 |
|------|------|
| 상단 | 카테고리 칩 **체육관 · 라이벌 · 모임** · 지역 검색 · 문의 |
| 하단 시트 (모바일) | 체육관/라이벌 목록 · 선택 시 상세 |
| 우측 패널 | 핀·카드 클릭 → 장소 미리보기·상세 |
| 더보기 메뉴 | 홈 · 찜(필터) · 내 문의 · **명패 · 라이벌 카드** · 체육관 등록 · 관장 입점 |

> 카테고리는 칩 **한 줄만**. 찜은 칩이 아니라 체육관 하위 필터.  
> 관↔관 **교류** 칩·화면은 Level 3 (`docs/gym-exchange.md`). 출시 UI에 넣지 않음.  
> 지도 앱 **흐름·자리**만 참고. 구글/네이버 UI·로고·타일 복제 금지. MANTLE 톤 유지.

### 체육관 범위

- GPS 또는 지역 검색이 끝나면 상단에 `서울 입점관 N곳`처럼 도시 단위 입점 수를
  표시한다. 국내 주요 도시는 로컬 좌표로, 그 밖의 지역은 Photon 역지오코딩으로
  도시명을 보완한다.
- 하단 목록은 `내 주변`과 `전체 입점관` 두 범위로만 나눈다. 내 주변에는 지도·입점
  결과를 함께 보여주고, 전체 입점관에는 승인된 입점 데이터만 보여준다.
- 도시 집계는 주소를 우선하고 좌표 반경으로 보완한다. 지도 좌표가 없는 입점관은
  전체 목록에서 `위치 확인 필요`로 표시해 집계 정확도 문제를 숨기지 않는다.
- 입점관 목록은 먼저 표시하고 OSM 결과는 최대 6.5초 동안 별도로 받아 합친다.
  OSM 결과는 30분 캐시하고 장애 시 최대 7일의 이전 결과를 사용한다.
- 위치 권한이 없거나 거부되면 기존 지역 검색을 사용한다. 자동 권한 요청은 하지 않는다.

**라이벌 카드 편집과 지도 레이어는 현재 코드에 남은 프로토타입이다.**

공개 출시 기능으로 보지 않으며, 후속 Level 3 명세는 `docs/later.md`가 기준이다.

### 라이벌 지도 (프로토타입 · 출시 제외)

- 공개 라이벌 카드가 있는 활동 권역 전체가 한 지도에 들어오도록 자동으로 범위를
  맞춘다.
- 같은 권역의 프로필은 하나의 핀으로 묶고, 최대 3명의 이니셜과 공개 인원 수만
  지도에 표시한다. 프로필 사진 필드와 실시간 위치는 추가하지 않는다.
- 권역을 선택하면 공개 프로필 목록, 프로필을 선택하면 체급·경력·강도·희망 시간과
  기존 `관심 보내기 → 상호 관심 → 대화` 행동을 보여주는 프로토타입이 있다.
- 공개 정보는 사용자가 라이벌 카드에 입력한 활동 권역이며 정확한 GPS, 현재 위치,
  연락처, 이동 기록은 표시하지 않는다.
- 현재 지도 좌표 변환은 `SEARCHABLE_AREAS`에 등록된 권역이 기준이다. 해외 권역
  자동 좌표 변환은 공개 카드 밀도가 확보된 이후 단계로 둔다.
- 이 구조는 최종 제품 결정이 아니다. 공개/비공개, 요청 수락, 차단·신고, 위치 비식별과
  RLS를 함께 재설계하기 전에는 출시하지 않는다.

### 모임 게시판 (MVP)

- 첫 화면은 `모집 중 / 지난 모임`과 지역·체육관 검색만 둔다. 목록에서는 상태,
  일정, 장소, 인원, 참가비만 한 행으로 훑는다.
- 행을 선택하면 상세 한 화면에서 조건을 확인하고 `참가 신청` 또는 `대화하기`를
  수행한다. 작성 화면도 목록과 동시에 노출하지 않는다.
- 디시인사이드의 빠른 목록 탐색만 참고한다. 익명 글, 자유 게시판, 댓글, 추천 경쟁은
  지역 운동 약속의 신뢰를 떨어뜨리므로 적용하지 않는다.
- 기존 일정·신청·주최자/신청자 대화 데이터와 Supabase 구조는 그대로 사용한다.
- 체육관 대여·체험·예약은 기존 문의 유형으로 유지한다. 메시지 알림 확장은 나중이다.

| 앱 | 빌린 구조 | 안 가져온 것 |
|----|-----------|--------------|
| **당근** 비즈프로필 | 찾기 → **가게 홈**(커버·소개·가격) → 문의·채팅 | 단골·쿠폰·후기 피드 |
| **플랩** | 장소/매치 카드 → **상세** → 신청(행동 1개) | 소셜 매치·레벨·구장 예약 풀스택 |

| **더코너류** | 사용자가 **내 체육관**을 프로필에 연결 | 지금 전역 커뮤니티 피드 |
| **Google Maps** | 현재 위치·거리·지역 문맥을 먼저 보여주는 주변 탐색 | 범용 카테고리·리뷰·광고 시스템 |

## 관 상세 = 가게 홈 (잠금)

한 장면: **커버 사진 · 관 이름 · 소개 · 위치 · 이용권 · 문의하기(또는 받은 문의)**.  
상세는 우측 패널에서 연다. 커뮤니티는 한 줄 자리만.

코드: `GymDetailPanel.jsx`

## 체육관 지도 — 보조 행동

| 행동 | 흐름 |
|------|------|
| **내 체육관으로 등록** | 지도 핀 → 상세 → 프로필 소속 저장 |
| **새 체육관 등록** | 없는 장소 제보 → 이름·주소·좌표 → 승인 대기 |
| **내 문의** | 보낸 문의 → 미리보기 → 대화 |
| **모임** | 게시판 행 탐색 → 상세 → 참가 신청 → 주최자·신청자 대화 |
| **관장 입점 관리** | 입점 신청·수정 · 승인 상태 · 받은 문의 |
| **라이벌 카드** | 프로토타입만 유지 · 현재 출시 제외 · `later.md`의 Level 3 후보 |

SQL: `dojo_inquiry_chat.sql` + `dojo_inquiry_chat_inbox.sql`  
안 읽음 확장·푸시·Realtime은 나중.

연락처는 공개하지 않는다. 답장은 앱 대화가 기본.
