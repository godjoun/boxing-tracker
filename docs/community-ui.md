# 커뮤니티 UI 설계 — 승인용

> **전제:** IA 잠금 `docs/community-ia.md` · Vision Loop · Community Principle 고정.  
> **상태:** 목적 분리 잠금 — 피드 / 일정 / 제안 각각 한 목적. 기록=프로필 흔적. 좋아요·뱃지·랭킹 제외. WDC 비주얼 복제 아님.  
> 출시 색: 기본 화이트 · 다크 버건디 `#8A2E2E` (전면 화이트 테마는 다음 작업).

## 설계 원칙

1. 한 화면 한 행동  
2. 허브 = 다음 교류 / 프로필 = 지난 증명  
3. 메인 CTA 화면당 버건디 하나  
4. 기존 기능 유지 · 정보 구조·계층·여백·CTA만 재배치  
5. Vision Loop에 역할 없는 UI 블록 추가 금지  
6. **Community Principle:** 새 교류를 만들거나 프로필 신뢰를 높이는가?  
   좋아요·조회수·배지 경쟁보다 실제 복싱 활동 우선 (`docs/community-ia.md`)

## 화면 지도

```text
커뮤니티
├─ C0 게이트 — 지역
├─ C1 게이트 — 내 체육관 (선택·건너뛰기 가능)
├─ C2 교류 허브 ← 기본 랜딩
├─ C3 체육관 목록/지도
├─ C4 체육관 상세
├─ C5 라이벌 목록
├─ C6 라이벌 카드/상세
├─ C7 모임 목록
├─ C8 모임 상세 · 신청
├─ C9 나 (개인 활동)
├─ C10 대화 (문의/모임/라이벌 — 기존 모달 재사용)
└─ (프로필 P1) 교류의 흔적 — 커뮤니티 결과 면
```

관↔관 전용 화면은 **출시 UI에 넣지 않음**. 허브에 「이후」자리만.

## C0 · 지역 게이트

| 항목 | 내용 |
|------|------|
| 주인공 | 지역 선택 |
| 한 행동 | 지역 정하기 |
| 주 CTA | 지역 선택 / 내 주변 |
| 뒤로 | 지도 전체, 칩, 목록 |
| Loop | 교류 진입 조건 |

---

## C1 · 내 체육관 게이트

| 항목 | 내용 |
|------|------|
| 주인공 | 다닐 관 고르기 |
| 한 행동 | 내 관 등록 **또는** 나중에 |
| 주 CTA | 이 관으로 등록 |
| Secondary | 건너뛰기 → 허브 |
| Loop | 소속 → 프로필 흔적의 기준점 |

목록 주 · 지도 보조. 첫 사용자는 여기서 끝나도 됨(등록 후 허브).

## C2 · 교류 — 목적별 화면 (보드 IA 재해석)

지도 없음. **한 화면 한 목적.** 목적 전환: `피드 | 일정 | 제안`.

### 공통

| 규칙 | 내용 |
|------|------|
| 상단 | 현재 목적 제목이 먼저 (교류 피드 / 일정 / 제안) |
| CTA | 화면당 버건디 **하나** |
| 카드 | 의미 하나 — 제목 → 핵심 → (상세에서) 세부 |
| 금지 | 좋아요·댓글·배지·랭킹·피드에 라이벌·관 제안 혼재 |

### C2-A 교류 피드

| 항목 | 내용 |
|------|------|
| 목적 | 다음에 고를 만남 목록만 |
| 주인공 | 교류 카드 |
| 계층 | 제목「교류 피드」→ 상태·제목·관·일시 → (탭하면) 상세 |
| 주 CTA | 모임 올리기 |
| Loop | 선택 → 상세 → 신청 → 일정 → 프로필 흔적 |

### C2-B 교류 일정

| 항목 | 내용 |
|------|------|
| 목적 | 예정·진행·완료 일정만 (+ D-day) |
| 주인공 | 다가오는 일정 |
| 주 CTA | 일정 만들기 (완료 탭에서는 흔적 안내) |
| Loop | 실시 → 완료 → 프로필 교류의 흔적 |

### C2-C 교류 상세

대관/모임 메타 · 일시 · 인원.  
주 CTA: 참가 신청 / 대화. (기록 남기기는 이후·프로필)

### C2-D 교류 제안

만남을 **제안**하는 입구만.  
지금: 모임 올리기(주) · 라이벌(보조 텍스트).  
관↔관 폼 = 출시 후 자리.

### C2-E 기록

별도 커뮤니티 화면 없음. **프로필 「교류의 흔적」**.

| 한 행동 | 관 하나 고르기 |
| 필터 | 내 주변 / 입점 · **찜** |

| 항목 | 내용 |
|------|------|
| 주인공 | 가게 한 장면 |
| 주 CTA | 문의 **또는** 내 관으로 등록 (맥락 하나) |
| Secondary | 찜 |
| Loop | 내 관만 프로필 전면 · 문의는 흔적 아님 |

| 화면 | 주인공 | 한 행동 | Loop |
|------|--------|---------|------|
| 목록 | 공개 카드들 | 카드 열기 | — |
| 상세 | 한 사람 | 관심 보내기 | 상호 → 대화 → 스파링 기록 → 프로필 |

| 화면 | 주인공 | 한 행동 | Loop |
|------|--------|---------|------|
| 목록 | 모집 중 일정 | 상세 | — |
| 상세 | 이 일정 | 참가 신청 | 완료 시 프로필 이력 |

올리기 = 목록의 명확한 Secondary/FAB 하나.

## C9 · 나 (개인 활동)

| 항목 | 내용 |
|------|------|
| 주인공 | 내가 진행 중인 교류 |
| 구역 | 내 관 · 라이벌 카드 · 신청·예정 · 대화 |
| 한 행동 | 이어갈 항목 하나 열기 |
| Loop | 완료 처리의 출발점 · 프로필과 맞닿음 |

「프로필에서 교류의 흔적 보기」텍스트 링크 하나.

---

## P1 · 프로필 「교류의 흔적」

커뮤니티 탭 밖이지만 **Loop의 정점**이라 UI에 포함.

```text
교류의 흔적
  교류 N · 스파링 N · 관 N     ← 요약(뼈대, 조용히)
  ─ 최근 ─
  [유형] 제목 · 장소 · 날짜     ← 주인공 = 이력 카드
  [유형] …
  전체 이력 →
```

| 항목 | 내용 |
|------|------|
| 주인공 | 최근 이력 카드 |
| 한 행동 | 이력 읽기 (상세는 이후) |
| 금지 | 랭킹, 배지 그리드, 좋아요 |
| Loop | 신뢰 → 허브로 「새로운 교류」유도 링크 가능 |

완료 직후(모임·스파링 기록 저장 시) 짧은 확인:  
「프로필에 오늘이 남았습니다」→ 프로필 / 닫기.

## 칩·헤더 공통

```text
[브랜드/타이틀]                    [나]
교류 | 체육관 | 라이벌 | 모임
```

- 활성 칩만 강조 · 버건디는 CTA에만  
- 허브가 기본 · 다른 칩은 깊은 파기

## Vision Loop × 화면 역할

| Loop 단계 | UI |
|-----------|-----|
| 훈련 | (홈·훈련 — 커뮤니티 밖) |
| 기록 | (기록 — 커뮤니티 밖) |
| 교류 | C2–C8 |
| 프로필에 흔적 | 완료 → P1 |
| 신뢰 | P1 표면 |
| 새로운 교류 | P1 → C2 / C5 / C7 |
| 다시 훈련 | 홈·훈련 |

## 구현 단계 제안 (승인 후)

1. **IA 반영 UI** — 칩 `교류·체육관·라이벌·모임` · 허브 골격 · 찜 필터 · 「나」진입  
2. **프로필 교류의 흔적** 블록(자리 + 기존 데이터로 채울 수 있는 것)  
3. 허브←→기존 체육관·라이벌·모임 연결  
4. 관↔관 · 고도 출석 = 이후 (`gym-exchange.md`)
