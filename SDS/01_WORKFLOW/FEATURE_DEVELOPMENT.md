# Feature Development SOP

## 목적

새 기능을 제품 문제와 사용자 행동에서 시작해, 검증 가능한 결과로 끝낸다.  
이 절차는 기능을 늦추기 위한 승인 체계가 아니라, 필요한 검토를 빠뜨리지 않기 위한 공통 언어다.

## 적용 대상

새 화면, 기능 변경, 사용자 흐름 변경, 데이터·외부 연동·출시 영향이 있는 모든 작업에 적용한다.

- 독자: CEO, AI 팀, 개발자
- 읽는 시점: 기능 요청을 받은 직후, 코드나 화면을 바꾸기 전
- 프로젝트 고유 산출물: 프로젝트 `docs/`
- 재사용 가능한 절차 개선: `SDS/`

## 시작 전 읽기

1. `SDS/00_BRAIN/`
2. 이 문서가 정한 변경 등급의 절차
3. 관련 회사 결정과 프로젝트 `docs/`의 제품 결정
4. 관련 `SDS/07_MEMORY/`의 증거 규칙과 검증된 패턴
5. 맡은 역할의 `SDS/02_AI_TEAM/` 문서
6. 프로젝트 `docs/`와 현재 코드

## 변경 등급

| 등급 | 대상 | 최소 절차 |
| --- | --- | --- |
| 경량 | 문구, 스타일, 명백한 단일 버그 수정 | 문제 확인 → 관련 화면 검토 → 구현 → 해당 범위 검증 → 결과 기록 |
| 표준 | 일반적인 기능, 새 사용자 흐름, 기존 기능의 의미 있는 변경 | 아래 전체 공통 단계 |
| 중대 | 데이터 모델, 보안·권한, 결제, 외부 API, 아키텍처, 출시 위험 | 표준 절차 + 구현 전 명시적 승인 + 회귀 검증 + 출시 판단 |

등급이 불명확하면 더 높은 등급으로 시작하고 CEO에게 확인한다.

## 공통 단계

### 1. 문제와 사용자 행동 정의

- Product Strategist가 해결할 문제, 대상 사용자, 기대 행동을 한 문장으로 정리한다.
- “무엇을 만들까”보다 “사용자가 무엇을 더 쉽게 할까”에 답한다.
- 다음 단계 조건: 성공 기준이 관찰 가능하게 정의되어 있다.

### 2. 제품·브랜드 검토

- Product Strategist가 제품 우선순위와 기존 기능의 충돌을 확인한다.
- UX Designer가 프로젝트의 브랜드·제품 원칙을 확인한다.
- 프로젝트에만 적용되는 근거와 결정은 `docs/`에 남긴다.
- 다음 단계 조건: 만들지 않을 범위와 핵심 행동이 분명하다.

### 3. UX 설계

- UX Designer가 진입점, 주요 행동, 완료 상태, 빈 상태와 오류 상태를 설계한다.
- 화면의 주인공은 하나이며, 새 기능이 기존 흐름을 방해하지 않는지 확인한다.
- 다음 단계 조건: 구현할 화면 상태와 사용자 흐름을 설명할 수 있다.

### 4. 기술 구현

- Frontend Engineer가 현재 코드와 데이터 흐름을 확인한 뒤 최소 범위로 구현한다.
- 보안, 데이터 손실, 외부 서비스, 기존 기록의 호환성 위험은 중대 변경으로 올린다.
- 다음 단계 조건: 코드가 기능 요구와 설계 범위를 충족한다.

### 5. 검증과 리뷰

- Frontend Engineer가 린트·테스트·빌드를 위험도에 맞게 실행한다.
- UX Designer가 핵심 사용자 흐름과 모바일 상태를 확인한다.
- Product Strategist가 성공 기준에 맞는지 확인한다.
- 다음 단계 조건: 알려진 실패 조건, 회귀 위험, 미검증 항목이 기록되어 있다.

### 6. 출시 판단

- Release Manager가 영향 범위, 롤백 가능성, 검증 결과를 확인한다.
- 중대 변경은 CEO의 명시적 출시 승인이 필요하다.
- 다음 단계 조건: 출시, 보류, 추가 검증 중 하나가 분명히 결정됐다.

### 7. 결과 기록

- 회사 전체에 적용되는 장기 결정은 `SDS/00_BRAIN/DECISIONS.md`에 기록한다.
- 제품 전용 결정과 근거는 프로젝트 `docs/`에 기록한다.
- 프로젝트에만 유효한 명세·검증 결과는 프로젝트 `docs/`에 기록한다.
- 짧은 작업 관찰과 실수는 `SDS/06_LOGS/`에 남긴다.
- 반복되는 문제는 Workflow, Template, Automation 개선 후보로 전환한다.

## 완료 기준

작업은 코드가 작성됐다고 끝나지 않는다. 다음을 만족하면 완료다.

- 사용자의 핵심 행동이 더 쉬워졌거나, 해결하려던 문제가 줄었다.
- 변경 등급에 맞는 검증이 끝났다.
- 중요한 결정과 미해결 위험이 적절한 위치에 기록됐다.
