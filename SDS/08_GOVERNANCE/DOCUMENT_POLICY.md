# Document Policy

## 문서 정보

- 소유: SDS
- 독자: CEO, AI 팀, 개발자
- 읽는 시점: 새 문서를 만들거나 기존 문서를 이동하기 전

## 생성 전 필수 판단

모든 새 문서는 아래 세 가지에 답한다.

1. 누가 소유하는가? — SDS, 회사 운영, 프로젝트 `docs/`
2. 누가 읽는가? — CEO, AI, 개발자, 프로젝트 팀
3. 언제 읽는가? — 기능 개발 전, 코드 작성 전, 배포 전, 회고 때

세 답이 불명확하면 문서를 만들지 않고 위치와 이유를 먼저 제안한다.

## 위치 기준

- 재사용 가능한 회사 원칙·절차·역할·템플릿은 `SDS/`
- 여러 프로젝트의 진행·우선순위는 `SDS/03_MANAGEMENT/`
- 제품별 기능, UX, API, 피드백, 원본 Evidence는 프로젝트 `docs/`

## 유지 규칙

- 문서는 현재 상태를 기록한다. 계획은 계획으로, 가설은 가설로 표시한다.
- 중복된 원본을 만들지 않는다. 원본을 하나 정하고 다른 문서는 링크한다.
- 더 이상 읽는 시점이나 독자가 없는 문서는 삭제 대신 상태와 대체 위치를 기록한 뒤 정리한다.
